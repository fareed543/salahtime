## 1. Request

Feedback on the masjid display board (screenshot of Usmaniya Jamia Masjid, 26 Oct 2026):

- "Show current salah start and End time as well"
- "Show Nafil Namaz in the board as well"
- "Is count down showing for azan or jamat? It should be for azan. Show jamat count down."
- "Give some sound probably beep when it reaches to azan time and jamat time."
- "For colors can we show a color selector so that masjid management can set the color based on their ambiance."

Decisions taken with the requester (2026-10-26): colours are set by the masjid
owner and saved on the masjid; nafil = Ishraq, Chasht, Awwabin, Tahajjud; both
countdowns shown side by side; makruh times (Sunrise, Zawal, Sunset) shown too.
Board layout approved 2026-10-27 (table board, "Option C") with the Karachi
method and the device timezone — mock-ups `board-emerald.png`,
`board-sand.png`, `board-midnight.png` in this folder (source
`board-mockup.html`).

## 2. Goal & Acceptance Criteria

**Goal:** the board tells worshippers when each salah's waqt starts and ends,
when nafil and makruh times are, how long until the next azan and the next
jamat, sounds a beep at each, and uses colours the masjid chose.

| # | Given / When / Then | Platform |
|---|---|---|
| AC-1 | Given the masjid has a map pin, the salah table shows Starts and Ends columns beside Azan and Jamat (e.g. Fajr 04:50 AM – 06:02 AM), calculated for the masjid's pin and madhab. Jumu'ah uses Dhuhr's window. Without a pin those two columns are hidden. | Web + Android |
| AC-2 | Given a pin, two tables under the salah table list Nafil (Tahajjud, Ishraq, Chasht, Awwabin) and Makruh (Sunrise, Zawal, Sunset), one row each with Starts and Ends. The nafil window running now is outlined and tagged "Now". Without a pin both tables are hidden. | Web + Android |
| AC-3 | The clock panel shows two countdowns: "<salah> azan in hh:mm:ss" and, in its own block, "<salah> jamat in hh:mm:ss", each with its clock time. After Isha both roll to tomorrow's Fajr ("tomorrow"). During the 10-minute jamat window the jamat countdown is replaced by "<salah> jamat in progress" (as today). | Web + Android |
| AC-4 | When the clock reaches an azan time the board plays a short beep pattern (3 short beeps); at a jamat time a different pattern (1 long beep). Each fires once per salah per day, not again on reload within the same minute. | Web + Android |
| AC-5 | A bell button in the display controls turns sound on/off for that screen (saved on the device, default on). If the browser blocks audio until a tap, the board shows a one-line "Tap to enable sound" hint that disappears after the first tap. | Web + Android |
| AC-6 | On the masjid edit form the owner sees "Display colours": Background, Card and Highlight colour pickers, plus "Reset to default". Saving stores them on the masjid. | Web + Android |
| AC-7 | When the masjid has saved colours, every display screen of that masjid uses them (after its next 10-minute refresh or reload); text colour on each is chosen automatically for contrast. The palette menu gains a "Masjid colours" option, selected by default; the five built-in themes remain selectable per screen. | Web + Android |
| AC-8 | Older app versions saving the masjid without the colour field keep the saved colours (same rule as latitude/longitude). Invalid values (not `#rrggbb`) are rejected by the API. | API |

**Out of scope:** a per-masjid choice of calculation method (uses Karachi, see Q1); custom/uploaded beep sounds or azan audio; colour editing from the back office (read-only there); changing what counts as "past"/"next" for card highlighting.

## 4. Design Delta

**FDS (Masjid display):**
- DSP-W1 Waqt window per card = `WaqtService.getTimes(today, masjid.latitude, masjid.longitude, deviceTzOffset, 'karachi', madhab)`; Fajr–Sunrise, Dhuhr–Asr, Asr–Sunset(−3m), Maghrib–(+45m), Isha–next Fajr, as the app's own prayer screen already shows. Madhab from the masjid (`hanafi`/`shafi`), default Hanafi.
- DSP-W2 Nafil strip: Ishraq, Chasht, Awwabin, Tahajjud. Makruh strip: Sunrise (`tulu`), Zawal, Sunset (`gurub`). Current window highlighted.
- DSP-C1 Next azan = earliest today's azan after now, else tomorrow's Fajr azan. Next jamat = earliest today's jamat after now, else tomorrow's Fajr jamat. (Replaces the single jamat-or-azan countdown.)
- DSP-S1 Beep at each azan and jamat minute, once per salah per day; patterns: azan 3×200 ms at 880 Hz, jamat 1×900 ms at 660 Hz (Web Audio oscillator, no audio file). Sound toggle per screen, default on.
- DSP-K1 Masjid colours: owner sets bg/card/accent; board derives `--surface`, `--surface-border`, `--text`, `--muted`, `--accent-text` from them by luminance so text is always readable. "Masjid colours" is the default theme when set; a screen's own theme choice still overrides it locally.

**HLD:** display component gains a small pure helper `masjid-display-utils.ts` (countdown targets, beep schedule, colour derivation) so it is unit-testable; API change limited to one column through the existing save/details actions.

**LLD:** None (each unit is small; covered by the helper's unit tests).

**Layout (approved 2026-10-27):** landscape screens use two columns with no scrolling. Left: masjid name and address; the salah table (Salah + Arabic name, Starts, Ends, Azan, Jamat; next salah row filled with the highlight colour, past rows dimmed); Nafil and Makruh tables side by side. Right: a highlight-colour panel with clock, Gregorian and Hijri dates, azan countdown, jamat countdown block, beep note and last-updated date. Portrait screens stack the panel under the tables and may scroll.
