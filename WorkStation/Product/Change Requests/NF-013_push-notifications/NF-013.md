## 1. Request

> Is push notification working — when I publish anything in the BO, will everyone who installed the app get the
> notification? … I want to make it work. Is that free or do I have to pay?

Answer on cost: Firebase Cloud Messaging is free on the no-card Spark plan, with no per-message charge. The API
(PHP) sends the messages, so no paid Firebase product (Cloud Functions) is needed.

## 2. Goal & Acceptance Criteria

**Goal:** an announcement published in the back office appears as a notification on every updated Android app that
allowed notifications, and tapping it opens the app on that announcement.

| # | Given / When / Then | Platform |
|---|---|---|
| AC-1 | Given the updated app, on first use of a notification-related screen (not first launch), it explains and asks Android's notification permission once | Android |
| AC-2 | Given permission, the app subscribes to topic `all-users` and sends its device token to the API (with the user id when signed in) | Android |
| AC-3 | When an admin publishes in Back office → Notifications, the API sends one FCM HTTP v1 message to topic `all-users`; the back office shows the real result ("Sent to all app users" / "Not sent: …reason") | BO + API |
| AC-4 | The notification shows in an "Announcements" channel with the app icon; tapping it opens the app on the announcement | Android |
| AC-5 | Blog events (approved / rejected / proposed) push to the author's own devices only, via the same sender | API |
| AC-6 | Every failure is logged; tokens FCM reports as invalid (`UNREGISTERED`) are deleted | API |
| AC-7 | "Send test to my phone" in the back office sends to the admin's own devices only | BO |
| AC-8 | Announcements list in the app (Profile menu → Notifications), so users who refused permission still see them | Android + Web |

**Out of scope:** website (browser) push; iOS; scheduled sends; per-city targeting (later: topics per city).

## 4. Design Delta

- **Delivery:** topic `all-users` for announcements (one API call, no token list to maintain); stored tokens only
  for per-person messages (blog author, "send test to my phone").
- **Credential:** service-account JSON on the API server; the API exchanges it for a short-lived OAuth2 token
  (cached ~50 min) and calls `https://fcm.googleapis.com/v1/projects/<project-id>/messages:send`.
- **Message:** `notification {title, body}` + `data {type: "announcement", id}`; Android channel `announcements`.
- **Permission:** asked in context (a short explanation card, then the system prompt), not at first launch.
