## 2. Goal & Acceptance Criteria

**Goal:** raise search clicks by giving each prayer its own page and putting the actual time in the search snippet, **with no visible change inside the Android app**.

"Mobile app" here means the Capacitor Android app (`Capacitor.isNativePlatform()`). Phone **browsers** get the changes: Google indexes the site with a phone-sized browser (SEO-32), so hiding them from phone browsers would hide them from Google.

| # | Given / When / Then | Platform |

## 4. Design Delta

**How the Android app stays unchanged (FDS rule PT-SEO-1):** every new visible element is rendered only when `!Capacitor.isNativePlatform()`, the existing pattern (SEO-12). The new routes are reachable only by URL, and the app has no address bar and no links to them. The default-city fallback (AC-6) applies only on the web branch, which already exists (`salahtime.component.ts:128`), so the app keeps asking for location first. Titles and meta tags have no visible effect in the app.

**FDS (new rules):**
- **PT-SEO-1** Website-only: prayer pages, prayer links, default-city fallback. Android: unchanged.
- **PT-SEO-2** Prayer page = one prayer's start–end today for the chosen/route/default city + other prayers + text + FAQ. Default city: saved city → else New Delhi.
- **PT-SEO-3** Prayer city versions exist only for the 30 `HOME_POPULAR_CITIES` + cities seen in Search Console queries (Indore, Surat, Aligarh, Kanpur, Kolkata, Pune): **9 × ~32 ≈ 290 pages**, not 9 × 2,103 (thin, near-duplicate pages hurt the whole site).
- **PT-SEO-4** Snippet times use method Karachi + Hanafi (the app defaults) and IST. The page body says "Times shown for Hanafi Asr; change in Settings".
- **PT-SEO-5** Title format: `<Prayer> Time Today in <City> – <h:mm AM/PM> | SalahTime` (≤ 60 chars, SEO-01). Description lists the day's five prayers.
- **PT-SEO-6** Prerendered times refresh daily at 00:05 IST through the scheduled deploy.

**HLD:** new lazy `PrayerFocusModule` (Prayer Times module); `seo-content.ts` gains prayer builders shared by the app and the prerender (SEO-03, one source); prerender gains a times step; CI deploy gains a daily trigger.

**LLD:** None needed — one component, pure builder functions.
