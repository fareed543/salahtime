## 1. Request

"The masjid timing-board feature reads a photo of a masjid's timing board into azan/jamat timings. Today it calls Claude only. Add ChatGPT (OpenAI) as a second provider. In the back office, an option to pick the provider (Claude or ChatGPT) and enter that provider's details (API key, model, etc.); the API then uses the selected provider to read the board."

## 2. Goal & Acceptance Criteria

**Goal:** an administrator chooses, at runtime, which AI provider reads timing-board photos, and sets its key and model, without a deploy.

| # | Given / When / Then | Platform |
|---|---|---|
| AC-1 | Given Settings → "OCR Settings", when an admin picks Claude or ChatGPT, enters a key and model and saves, then the next board photo is read by that provider. | Back office |
| AC-2 | Saved API keys are never returned to the browser: only "key set" + last 4 characters are shown. A blank key field on save keeps the saved key. Keys never appear in logs. | Back office + API |
| AC-3 | Each provider keeps its own key and model, so switching back and forth does not lose the other provider's key. | Back office |
| AC-4 | Until the section is saved once, behaviour is identical to today: Claude, `ANTHROPIC_API_KEY` from `.env`, model `claude-opus-5-5`, same request body (effort, structured output, server-side fallback beta). | API |
| AC-5 | With ChatGPT selected, the photo is sent as a base64 data URL and the reply is JSON matching the same schema (`timings[]{salah, azan, jamat}`, `notes`), normalised through `MasjidTimings::normalize` exactly like Claude's. | API, Web + Android unchanged |
| AC-6 | A "Test connection" button checks the key + model as entered on screen (saved or not) without reading a photo and without token cost. | Back office |
| AC-7 | Errors show the same user-facing messages as today (not configured / busy / could not read / refused). | Web + Android |

**Out of scope:** automatic failover to the other provider when one fails; encrypting keys at rest (the SMS key is stored the same way today); per-masjid provider choice; providers other than Anthropic and OpenAI.

## 4. Design Delta

> As built, names differ from the first draft: settings class `OcrSettings` (section key `ocr`),
> endpoint `admin/test-ocr`, an abstract class `TimingBoardProvider` instead of an interface,
> back-office `OcrSectionComponent`. Default OpenAI model: `gpt-5`.

### 4.1 Storage — `bt_app_setting`, section `ocr`

Same mechanism as the SMS Provider section, so it changes at runtime and the key stays server-side:

```json
{
  "provider": "claude",                     // "claude" | "openai"
  "claude": { "apiKey": "...", "model": "claude-opus-5-5" },
  "openai": { "apiKey": "...", "model": "<admin-entered>" }
}
```

- Never saved → defaults from params/.env: provider `claude`, `ANTHROPIC_API_KEY`, `claude-opus-5-5`; OpenAI key from `OPENAI_API_KEY` (empty unless set) and a default model from params.
- `describe()` returns `apiKey: ''` plus `apiKeySet` / `apiKeyHint` (last 4) per provider — never the key.
- `normalize()`: blank key = keep the saved (or .env) key for that provider; a new "Clear key" checkbox per provider is **not** added (same as SMS).
- `validate()`: the selected provider must have a key and a model; key format `^[A-Za-z0-9_\-]{20,300}$`; model `^[A-Za-z0-9._:\-]{2,100}$`.
- Logging: provider errors log HTTP status, error type and up to 500 chars of the provider's error body (as today); request headers/body are never logged, so the key cannot leak.

### 4.2 API — provider interface

```
TimingBoardReader::read($path, $mime)          // unchanged signature, callers untouched
  ├─ settings = TimingBoardSettings::get()
  ├─ provider = settings.provider === 'openai' ? new OpenAiBoardProvider(key, model)
  │                                            : new ClaudeBoardProvider(key, model)
  ├─ text = provider->readBoard(imageBase64, mime, PROMPT, schema())   // returns the model's JSON text
  └─ shared: json_decode → check timings[] → MasjidTimings::normalize → {timings, notes}

interface TimingBoardProvider {
  buildRequest(image, mime, prompt, schema): array{url, headers, body}   // pure, unit-testable
  parseResponse(array decoded): string                                   // text, or throws refusal
  readBoard(...)                                                          // buildRequest → shared post() → parseResponse
  testConnection(): ?string                                               // null = OK, else message
}
```

- **Claude**: byte-for-byte today's body (model, `max_tokens 16000`, `fallbacks: default`, `output_config.effort medium` + `json_schema`, image block, prompt) and headers (`x-api-key`, `anthropic-version 2023-06-01`, `anthropic-beta server-side-fallback-2026-07-01`). Refusal = `stop_reason: refusal`.
- **OpenAI**: `POST https://api.openai.com/v1/chat/completions`, `Authorization: Bearer <key>`, body
  `model`, `max_completion_tokens 16000`, `response_format: {type: json_schema, json_schema: {name: "timing_board", strict: true, schema}}`, one user message with `[{type: image_url, image_url: {url: "data:<mime>;base64,..."}}, {type: text, text: PROMPT}]`. Text = `choices[0].message.content`; refusal = `choices[0].message.refusal` set, or `finish_reason: content_filter`. The existing schema already satisfies strict mode (all fields required, `additionalProperties: false`).
- Shared `post()`: today's curl options, one retry on network error / 429 / 5xx, same user-facing messages (429/529 → "busy", others → "could not read").
- **Test connection** (`POST admin/test-timing-board {values}`): `GET /v1/models/{model}` on the chosen provider with the entered (or saved) key — confirms key and model exist, costs no tokens. Returns `{ok, message}` or `{ok:false, error}`.

### 4.3 Back office — Settings → "OCR Settings" card

- Provider dropdown: Claude (Anthropic) / ChatGPT (OpenAI).
- For the selected provider: API key (password field with show/hide, placeholder "Saved key ending abcd", "Leave blank to keep the saved key") and Model (text input with the default as a hint).
- "Test connection" button, result alert under it (like the SMS test).
- Footer: last updated / "Not saved yet — ANTHROPIC_API_KEY from .env applies."

### 4.4 Fallback / errors

- No cross-provider failover (out of scope; can be a follow-up toggle).
- Claude keeps its server-side model fallback beta exactly as today.
- Selected provider has no key → "Reading timing boards is not configured on the server." (today's message).
- `bt_app_setting` missing → defaults (.env), as with every other section.

### 4.5 SQL

No schema change, so **no new Yii migration and no SQL file**. The section row is created by the first Save. `bt_app_setting` comes from `m261010_130000_create_app_setting_table.php`; its phpMyAdmin equivalent is `api/docs/sql/2026-10-10-production.sql:59`, already applied on production.
