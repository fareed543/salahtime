## 1. Request

> Ramadan 2027 starts around 8 February. Sehri/iftar pages per city need to go live by December to rank in time. Right now there's only one /sehri-iftar page.

## 2. Goal & Acceptance Criteria

**Goal:** a crawlable "Sehri and Iftar time in <city> — Ramadan 2027 timetable" page for every Indian city, live by early December 2026.

| # | Given / When / Then | Platform |
|---|---|---|
| AC-1 | When `/sehri-iftar/india/chennai` is requested, the raw HTML (no JavaScript) has title "Chennai Sehri & Iftar Time: Ramadan 2027 Timetable", its own canonical, an H1, the expected start date, and a 29/30-row table: date, Hijri day, Sehri ends, Iftar | Web |
| AC-2 | The same URL in a browser shows the Ramadan screen for Chennai (not the visitor's saved city) with the same table, and does **not** change the visitor's saved location | Web |
| AC-3 | Times match the app's Ramadan screen for that city with default settings (Karachi, Hanafi, default Sehri/Iftar offsets) | Web |
| AC-4 | Before Ramadan the pages do not change from day to day (no daily re-upload); from 1 Ramadan the title/description carry today's Sehri and Iftar | Web |
| AC-5 | Every Indian city page links to its Sehri/Iftar page; `/sehri-iftar` links popular cities and all cities; `sitemap-sehri-iftar.xml` lists every page | Web |
| AC-6 | `/sehri-iftar` title and text say Ramadan 2027 (today: "Ramadan 2026") | Web + Android |
| AC-7 | An unknown city (`/sehri-iftar/india/xyz`) returns 404 | Web |
| AC-8 | The Android app's Ramadan screen is unchanged (no SEO text, uses the saved location) | Android |

**Out of scope:** Ramadan pages for non-Indian cities (the prerender only computes Indian Standard Time today — `frontend/tools/prerender-seo.js:51`); Ramadan 2028; push notifications.

## 4. Design Delta

**FDS**
- RAM-01 URL: `/sehri-iftar/<country>/<city>`, same slugs as city pages; India only.
- RAM-02 Ramadan dates: Ramadan 1448 from the app's Hijri calendar with India's adjustment from `calendar-adjustments.json`. Today (Umm al-Qura, no adjustment): **Mon 8 Feb – Mon 8 Mar 2027 (29 days), Eid ul-Fitr Tue 9 Mar**. The page always says "expected, subject to moon sighting; India usually begins one day after Saudi Arabia". When an admin adds a 1448 adjustment for India, the next nightly build uses it.
- RAM-03 Table: one row per Ramadan day — Gregorian date + weekday, Ramadan day number, Sehri ends (`sahri`), Iftar (`iftar`), default offsets from `default-settings.json`; plus Fajr and Maghrib in a note ("Sehri ends N minutes before Fajr").
- RAM-04 Titles (≤ 60 visible characters before " | SalahTime"):
  - Before Ramadan: "Chennai Sehri & Iftar Time: Ramadan 2027 Timetable"; description: start date + first-day Sehri/Iftar.
  - During Ramadan: "Sehri 4:58 AM, Iftar 6:21 PM Today in Chennai – Ramadan 2027"; description: today + tomorrow.
  - After Eid until the next build year switch: unchanged timetable, title "…Ramadan 2027 Timetable".
- RAM-05 Page content (prerender and app, from `seo-content.ts`): H1 "Sehri and Iftar Time in Chennai – Ramadan 2027", intro with dates, the table, "Today in Chennai" box during Ramadan, FAQ (when does Ramadan 2027 start in India; Sehri/Iftar time today; how times are calculated; Laylat al-Qadr nights), links to nearby cities' Ramadan pages and the city's prayer-times page.
- RAM-06 City mode never changes the visitor's saved location or settings.
- RAM-07 Schema: `WebPage` + `BreadcrumbList` + `FAQPage` (FAQ visible on the page); no `Event` markup (the dates depend on moon sighting).

**HLD:** Ramadan module gains a routed city mode; SEO tools gain a Ramadan builder and sitemap. **LLD:** None (pattern identical to the city pages, CR-006).

**Deviations from §3/§4 (approved design):**
- The city view is a new component (`RamadanCityComponent`) in the Ramadan module instead of a "city mode" inside `RamzanComponent`: the same on every screen size, uses the default settings exactly like the prerender, and never touches the saved location (RAM-06) — simpler and safer than branching the existing screen.
- No new i18n keys: like the city SEO pages, the page text is the English SEO text from `seo-content.ts`, identical to the prerendered HTML. The unused key `RAMZAN_2026` (13 files) was left as it is.
- RAM-02 default for India without a back-office date: Umm al-Qura + 1 day, **30 rows**, the 30th marked "only if the Shawwal moon is not seen". The same rule runs in the build and the app.
